# Step 2: Version-controlling Your Manuscript

In this step you will:
1. Understand what version control means for writers
2. Save a new version of your manuscript each time you reach a milestone
3. Look back at earlier versions
4. Restore an earlier version if you change your mind

## What is version control?

Version control means keeping a history of every change you make to your files. Instead of saving files like:

- `chapter-1-final.docx`
- `chapter-1-final-v2.docx`
- `chapter-1-final-really-final.docx`

You save one file, `chapter-1.docx`, and GitHub remembers every time you changed it. You can see what changed, when, and go back to any earlier point.

## Part A: Edit a file directly on GitHub

The simplest way to save a new version is to edit your file on GitHub's website.

1. Open your repository on github.com.
2. Click on your manuscript file (for example, `chapter-1.md`).
3. Click the pencil icon (Edit file) in the top-right of the file view.
4. Make your changes — add a paragraph, fix a typo, rewrite a scene.
5. Scroll down to the "Commit changes" box.
6. Type a message describing what you changed, such as:
   > Fix typo in Chapter 1, paragraph 3
7. Click **Commit changes**.

GitHub now saves a new version of your file. Your previous version is still there — you have not lost anything.

## Part B: Upload a revised file

If you write in Word, Google Docs, or another program on your computer, you can upload the updated file:

1. Open your repository on github.com.
2. Click **Add file**, then **Upload files**.
3. Drag your revised manuscript file into the upload area. Use the **same filename** as before (for example, `chapter-1.docx`).
4. GitHub will ask if you want to update the existing file. Confirm.
5. Type a commit message, such as:
   > Upload revised Chapter 1 after editor feedback
6. Click **Commit changes**.

## Part C: Look at your version history

1. Open your repository on github.com.
2. Click on your manuscript file.
3. Click the **History** button (a clock icon) near the top of the file view.
4. You will see a list of every commit that touched this file, with the date, time, and commit message.
5. Click any commit to see what the file looked like at that moment.

## Part D: Restore an earlier version

1. From the History page, click the commit you want to go back to.
2. Click the file name to open that version.
3. Click the pencil icon (Edit file).
4. Scroll down and type a commit message, such as:
   > Restore Chapter 1 from March 3 draft
5. Click **Commit changes**.

GitHub saves this as a new commit, so you still have the later versions if you need them.

## Good commit messages for writers

Write commit messages that make sense months from now:

- Good: "Add Chapter 1 draft"
- Good: "Fix spelling in Chapter 3"
- Good: "Incorporate editor feedback on Chapter 2"
- Not helpful: "changes"
- Not helpful: "final version"
- Not helpful: "update"

## What version control protects you from

- Accidentally deleting a chapter and wanting it back
- Realizing a rewrite was a mistake and wanting the old version
- Not knowing which draft your editor was looking at
- Losing work if your computer breaks (your files are also on GitHub)
